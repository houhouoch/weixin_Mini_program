# 今天还能花｜微信小程序 MVP

一个只用本地数据回答“今天还能安全花多少钱”的原生微信小程序。项目无登录、无后端、无云开发、无第三方 UI 库，首页支持自定义发薪预算周期、固定支出明细、常用记账模板、周总结、逐笔收支、微信/支付宝账单导入与批次撤销、日期和区间回看纠错、完整本地备份恢复、Excel 导出、主题定制和隐私安全分享。

## 导入微信开发者工具

1. 打开微信开发者工具，选择“导入项目”；
2. 项目目录选择本仓库根目录：`C:\Users\admin\Documents\ChatGPT\小程序`；
3. AppID 可先使用 `project.config.json` 中的 `touristappid` 本地体验，或替换为你自己的小程序 AppID；
4. 项目类型选择“小程序”，点击导入并编译；
5. 首次进入设置预算周期、收入、固定支出和储蓄目标，再测试固定支出明细、常用模板、周总结、历史纠错和导出导入。

本项目不需要安装依赖，也没有构建命令。

运行主图为 1024 × 683、约 148 KB 的渐进式 JPEG。`docs`、`design-system`、`specs`、`tests` 和 `scripts` 通过 `packOptions.ignore` 保留在 Git 仓库但不进入微信主包；本地结构检查同时限制单张运行图小于 200 KB、运行主包原始文件小于 1.5 MB。最终上传体积以开发者工具报告为准。

## 数据字段

预算和记录使用本地 key `today-can-spend:v1`，结构包含：

- `schemaVersion`：当前为 5；
- `monthKey`：`YYYY-MM`；
- `budget.incomeCents`：每个预算周期的固定收入（分）；
- `budget.fixedExpenseCents`：固定支出（分）；
- `budget.savingGoalCents`：储蓄目标（分）；
- `budget.historicalSpentBeforeTrackingCents`：启用前已花（分）；
- `budget.trackingStartDate`：`YYYY-MM-DD`；
- `budget.cycleStartDay`：每月 1–28 日的预算周期起始日；
- `budget.activeCycleStartDate`：当前预算周期起点；
- `budget.fixedExpenseItems[]`：最多 12 项固定支出解释明细，不生成流水；
- `budget.categoryBudgets[]`：仅为 schema 5 旧数据兼容保留，当前页面保存时写为空数组；
- `transactions[]`：本月交易，包含本地 ID、金额分、`expense/income` 收支方向、分类 ID、可选用途/来源和本地时间戳；新导入记录另含本地 `importBatchId` 与 `importedAt`；
- `processedCommandIds[]`：最近交易命令 ID，用于幂等防重复。
- `quickTemplates[]`：最多 8 个本地常用收支模板；点击后仍通过 `addTransaction()` 记账。
- `history[]`：最多保留 36 个已结束月份的启用前汇总与真实逐笔记录，用于年度回看。

页面不会直接调用缓存 API。交易模块只公开返回 Promise 的 `addTransaction(command)` 与 `listTransactions(options)`：创建、修改、删除、账单导入和批次撤销分别通过 `addTransaction({ action: 'create' | 'update' | 'delete' | 'import' | 'undoImport' })` 完成；`listTransactions` 可按日期、时间段、收支和分类读取当前月或归档明细，也可读取最近可撤销导入批次。

支出分类为餐饮、交通、购物、日用、娱乐、医疗、人情、其他；收入分类为外快、奖金、工资、报销、转入、红包、退款、其他收入。旧版 `schemaVersion: 1/2/3/4` 数据会原地无损迁移到版本 5；旧预算默认为每月 1 日起始，配置明细和模板为空。存储 key 保持不变。

主题单独保存在 `today-can-spend:theme:v1`。用户只能从 6 套预设中选择，并在限定范围内调整色相、背景温度和亮度；超支红、警示黄及其文字色由系统锁定。重置本月会清空当前设置与当前月记录，但不会删除已经归档的往月数据或主题偏好。

消费回看的月/年总额可包含“启用前已花”，但趋势、最高日/月和分类排行只使用具有真实时间与分类的逐笔记录，不会把汇总金额伪造成历史明细。自定义时间段的起止日都计入，只统计真实逐笔支出，排除收入和“启用前已花”；分类可继续下钻到区间流水并直接纠错。

## 计算公式

```text
本周期日常消费总预算 = 固定收入 + 本周期逐笔额外收入 - 固定支出 - 储蓄目标
今天之前已花 = 启用前已花 + 小程序内今天之前记录
今日建议额度 = floor(max(日常预算 - 今天之前已花, 0) / 含今天的剩余天数)
今天还能花 = max(今日建议额度 - 今日已花, 0)
本周期剩余可用 = 日常预算 - 启用前已花 - 本周期全部支出
```

全部金额以整数分保存和计算。预算周期可从每月 1–28 日开始，例如 15 日至次月 14 日；自然月只负责存档和月/年回看。今日金额最低为 0；周期剩余允许为负，页面按设置显示“本月超支”或“本周期超支 ¥绝对值”，不显示可用负数。

预算设置另外满足：固定收入必须大于 0；固定支出不得超过固定收入；固定支出明细合计不得超过固定支出总额；固定支出 + 储蓄目标不得超过固定收入与已记录额外收入之和；固定支出 + 启用前已花 + 已记录支出也不得超过该收入合计。真实流水不会因预算不足被拒绝，而是进入超支预警。分类预算输入与提醒已从页面移除。

日回看中的周总结只统计周一至今天的真实支出，并与上周相同星期跨度比较；收入、固定支出明细和启用前汇总都不会混入。

## Excel 导出

展开“记录与历史”，点“导出并打开 Excel”。小程序会在本机生成真实 `.xlsx`，包含当前月与归档月的日期、时间、收支、分类、用途/来源、金额和数据来源，并分别显示收入与支出合计。

启用前已花是没有日期和分类的汇总，不会被伪造成逐笔流水。文件只写入小程序用户目录，不上传，不含 OPENID 或身份信息。`wx.openDocument` 文档菜单、`wx.shareFileMessage` 和 PC 端保存需在微信开发者工具/真机验证。

## 导入微信或支付宝账单

两种平台共用“从微信会话选择文件”入口，按表头自动识别：

1. 微信：申请个人账单，使用邮件密码解压，把 `.xlsx` 或 `.csv` 发到任意微信会话；
2. 支付宝：导出交易明细 `.csv`，把文件发到任意微信会话；
3. 展开“记录与历史”并选择文件；
4. 核对平台、日期范围、新增/重复、支出、收入/退款和跳过原因，再确认导入。

账单只在本机解析，不上传。微信只导入最近 36 个月至当前时刻的有效支出。支付宝 CSV 兼容 GB18030/UTF-8：有效消费和收入会导入；还款、信用借还、理财及其他不计收支会跳过。全额退款与同订单同金额的已关闭原交易成对抵消；部分退款或跨期消费退款记为“退款收入”，用于冲减真实消费净额。交易单号只生成不含原文的本地去重指纹，订单号和账号原文不保存。导入后可按日期修改、删除，Excel 标记对应平台来源。加密 ZIP 不能直接选择；银行格式仍是后续路线图。

V1.9 起每次实际新增的导入记录会带本地批次 ID。“记录与历史”显示最近 5 个仍有记录的批次，二次确认后可整批撤销；不会误删手工记录、其他批次或恢复已经手动删除的记录。旧版本导入记录没有批次 ID，仍按逐笔纠错。

## 完整数据备份与恢复

“记录与历史”可生成 `.json` 完整备份，包含预算、当前和最多 36 个月历史流水、导入批次及主题。文件只在本机生成，可以转发或在 PC 端保存，不含 OPENID、昵称、头像或平台订单号原文。

恢复时选择本产品 JSON 备份，先查看备份时间、月份范围和流水笔数，再二次确认覆盖。格式、状态 schema 和主题参数均通过后才写入；状态持久化失败会恢复原主题并保留原状态。Excel 是展示文件，不能用于恢复。

## 分享与隐私

- 调用 `wx.showShareMenu` 开启好友和朋友圈；
- 好友按钮使用 `open-type="share"`；
- 分享标题包含预算人格、使用天数、记录笔数和本月累计花费摘要；
- 分享路径只含 `from=share`，不携带逐笔交易、OPENID、昵称、头像或其他身份信息；
- 接收者只会读取自己设备上的本地数据。
