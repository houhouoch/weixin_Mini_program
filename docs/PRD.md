# PRD：今天还能花（微信小程序 MVP）

- 文档状态：V1.2 设计基线，功能实现待排期
- 版本：1.2
- 日期：2026-08-09
- 产品形态：微信原生小程序，单页，本地存储

## 1. 产品概述

“今天还能花”帮助刚工作 1–5 年、收入相对固定但没有稳定预算习惯的年轻上班族，在准备发生一笔可选消费前，用几秒钟确认：

> 今天还可以放心花 ¥XX.XX。

产品不试图替代记账软件或提供理财建议，只验证一个最小闭环：设置本月预算 → 查看今日安全额度 → 消费后记一笔 → 额度立即更新 → 次日继续回来查看。

## 2. 产品目标与成功信号

### 2.1 MVP 目标

1. 用户能在 2 分钟内完成首次设置；
2. 用户能在 15 秒内记录金额、消费分类和可选用途；
3. 用户理解主金额与三个辅助指标的关系；
4. 用户愿意跨天再次打开；
5. 分享不会泄露身份和逐笔消费数据。
6. 用户无需进入复杂报表，就能比较今天、昨天、前天以及日/月/年消费趋势；
7. 用户可以选择自己喜欢的页面气质，同时超支和警示仍保持一致且可读。

### 2.2 本地事件信号

预留统一 `trackEvent()`：

- `app_open`
- `transaction_saved`
- `result_viewed`
- `share_friend`
- `share_timeline_guide`
- `share_entry_open`

MVP 不接服务端，事件仅走可替换的空实现/本地调试输出。事件 payload 只能包含页面状态、入口、布尔值和计数区间，不得包含逐笔金额、预算金额、OPENID 或身份信息。

## 3. 用户与核心场景

### 3.1 目标用户

- 刚工作 1–5 年的年轻上班族；
- 知道余额，但不知道余额中有多少可以自由花；
- 不愿学习复杂记账或预算体系；
- 在外卖、聚餐、购物、娱乐前需要快速判断。

### 3.2 核心任务

1. 首次设置收入、固定支出、储蓄目标与启用前已花；
2. 查看“今天还能花”；
3. 选择消费分类、填写可选用途和金额并记一笔；
4. 查看或删除最近 5 笔；
5. 修改或重置本月设置；
6. 跨天/跨月后继续得到正确结果；
7. 向好友或朋友圈分享不含隐私的产品结果摘要。
8. 快速查看日/月/年消费回顾；
9. 选择预设主题，或安全地微调主色与背景温度。

## 4. 功能范围

### 4.1 首次预算设置

在首页底部抽屉中填写：本月收入、固定支出、储蓄目标、开始使用前已花。字段均为人民币元，允许 0，不允许负数，最多两位小数。若今天是 1 日，历史已花默认 0。

抽屉必须解释“开始使用前已花”不包含固定支出，也不包含小程序内记录；底部显示“数据只保存在当前设备中，不会上传”。设置合法后才能保存。

### 4.2 核心结果

首页核心卡展示：

- 标题“今天还能花”；
- 超大金额 `¥XX.XX`；
- 当前状态文案；
- 今日建议额度、今日已花、本月剩余可用。

设置未完成或读取失败时不得显示伪造金额。

### 4.3 快速记一笔

提供消费分类、可选用途、金额输入框和“记一笔”按钮。分类使用固定快捷选项：餐饮、交通、购物、日用、娱乐、医疗、人情、其他；默认选中餐饮，用户可一键切换。用途用于描述实际去向，例如“咖啡”“午餐”“地铁”，最多 20 个字符，可以留空。

点击后进入保存中并锁定重复提交；只有本地持久化成功后才清空用途和金额、保留最近使用分类、收起键盘、刷新金额并显示成功反馈。

非法输入包括：空、0、负号、字母、多个小数点、超过两位小数、超过 `999999.99` 元。

### 4.4 最近记录与删除

显示当月最近 5 笔，包含分类、用途、本地时间、金额和删除入口。用途为空时显示分类名称；删除前显示：

> 删除这笔 ¥XX.XX 的消费记录？删除后预算会重新计算。

删除成功后立即刷新；没有记录时展示轻量空状态。

### 4.5 修改与重置

右上角设置入口打开同一抽屉并回填当前值。保存设置时保留已有记录。固定支出加储蓄目标可大于收入，但结果必须解释为什么今日额度为 0。

重置位于次要区域，确认文案：

> 将删除本月设置和所有消费记录，且无法恢复。确定继续吗？

### 4.6 跨天与跨月

页面 `onShow` 时按设备本地日期刷新。跨天保留记录并重新归类今日消费。检测到新月份时提示沿用设置或重新设置：沿用只保留收入、固定支出、储蓄目标，清空历史基线和交易，新启用日期设为当天。

### 4.7 分享

- 开启好友和朋友圈分享菜单；
- 好友按钮使用微信原生分享能力；
- 朋友圈使用右上角菜单引导；
- 标题使用“预算人格 + 使用天数 + 记录笔数 + 本月累计花费”的摘要；
- 路径只带 `from=share`；不携带交易、金额明细、OPENID 或身份信息；
- 分享进入者只读取自己的本地存储，没有数据时看到“开始我的支出记录”。

### 4.8 语义化余额状态

首页主视觉必须提供四种可辨识状态，不能只把同一张卡片换颜色：

1. 正常：森林绿，突出“今天还能花”；
2. 额度将尽：琥珀黄，显示剩余金额与“下一笔先想一想”；
3. 今日超额：珊瑚红，明确显示“已超 ¥XX.XX”，不得只显示 `¥0`；
4. 本月超支：使用更深的危险色，并解释本月已超出的金额与后续影响。

标题、金额/状态文案、进度条和状态标签必须同步变化，并提供 150–240ms 的连续过渡。危险状态仍保留原消费插画作为品牌背景，但通过文字承载层保证可读性。

### 4.9 消费回看

首页增加轻量“消费回看”模块，使用 `日｜月｜年` 分段切换，不新增 tabBar 或独立报表页。

- 日：展示今天、昨天、前天金额，最近 7 天柱状趋势和本周消费最高分类；
- 月：展示本月总额、日均、最高消费日、最高分类和按周/日期趋势；
- 年：展示全年总额、月均、最高月份和 12 个月趋势；
- 点击某日或月份时，后续可用底部抽屉查看明细，但不得新增页面层级。

图表只服务于“比较和回看”，不提供资产负债、预算预测、投资建议或可配置仪表盘。

### 4.10 主题工作室

设置抽屉增加主题入口，首版提供 6 套预设：暖森林、海岸蓝、日落珊瑚、午夜、青柠、黑白。用户可进一步微调主色调、背景温度和亮度，界面实时预览并提供恢复默认。

系统根据用户选择派生正文、表面和边框颜色，保证基础对比度。警示黄、超支红和对应文字对比度始终由系统锁定，不跟随用户主题变化。模块排序和自由配色器不进入本轮范围。

## 5. 计算口径

全部金额使用整数分。

```text
monthlyFlexibleBudget = income - fixedExpense - savingGoal
spentBeforeToday = historicalSpentBeforeTracking + recordedSpentBeforeToday
todaySuggestedBudget = floor(max(monthlyFlexibleBudget - spentBeforeToday, 0) / daysRemainingIncludingToday)
todayRemaining = max(todaySuggestedBudget - todaySpent, 0)
monthlyRemaining = monthlyFlexibleBudget - historicalSpentBeforeTracking - sum(records)
```

状态优先级：

1. `monthlyFlexibleBudget <= 0`：固定支出和储蓄目标已用完收入；
2. `monthlyRemaining < 0`：本月已超支；
3. `todaySpent > todaySuggestedBudget`：今日已超额；
4. `0 < todayRemaining <= floor(todaySuggestedBudget * 30 / 100)`：额度将尽；
5. 其他：正常。

当月剩余可以为负；今日还能花最低为 0。剩余天数含今天，最小为 1。

## 6. 数据模型

```js
{
  schemaVersion: 2,
  monthKey: "YYYY-MM",
  budget: {
    incomeCents: 0,
    fixedExpenseCents: 0,
    savingGoalCents: 0,
    historicalSpentBeforeTrackingCents: 0,
    trackingStartDate: "YYYY-MM-DD"
  },
  transactions: [
    {
      id: "local-id",
      amountCents: 1500,
      categoryId: "food",
      note: "咖啡",
      occurredAt: 0
    }
  ]
}
```

存储只在当前设备；不登录、不上传、不申请敏感权限。未知版本或损坏数据安全降级。版本 1 的旧交易在读取时迁移为 `categoryId: "other"`、`note: ""`，保留金额和时间；存储 key 保持不变以便读取旧数据。

### 6.1 V1.2 历史归档规划

当前 `schemaVersion: 2` 在跨月时清空交易，因此只能可靠生成当前月份以及本次启用后的日视图。要实现真实年视图，代码阶段必须升级为 `schemaVersion: 3`，把“当前月工作集”和“只读历史归档”分开保存，并为归档提供有上限的本地保留策略。

`historicalSpentBeforeTrackingCents` 只有汇总金额，没有日期和分类，不能反推旧日期趋势或分类占比。旧数据在日/月/年回看中应标注为“启用前汇总”，不得伪造历史柱状图。schema 3 只允许无损迁移，不得因升级删除当前记录。

## 7. 页面与交互结构

单页自上而下：安全区顶部与设置入口 → 插画化核心结果 → 预算进度 → 可折叠消费回看 → 分类/用途/金额快速记录 → 票据式最近记录 → 轻量分享入口。设置和主题工作室使用底部抽屉覆盖同一页面。

必须覆盖：读取中、首次空、记录空、保存中、成功、读取失败、保存失败、防重复、确认弹窗和跨月选择。

## 8. 视觉原则

- 使用原创编辑插画作为首页主视觉，建立与日常消费相关的品牌记忆；
- 暖奶油色纸张背景，森林绿、珊瑚橙和黄油黄作为主要色块；
- 内容通过纸带、色块和排版分区，不连续堆叠同形白色圆角卡片；
- 红色仅用于错误和超支；警示黄和超支红不受用户主题覆盖；
- 微信系统字体，数字使用稳定的系统无衬线字体；
- 预算进度只使用一条可读的比例轨道；消费回看仅使用轻量柱状趋势，不引入复杂财务图表；
- 主金额是唯一最高视觉层级；
- 触控目标至少 44 CSS px 等效尺寸；
- 窄屏、刘海区、底部手势区和超长金额均不遮挡。

## 9. 非功能要求

- 无第三方运行时依赖；
- 数据接口均返回 Promise；
- 页面不得直接访问缓存；
- 保存失败不得假装成功；
- 自动化测试覆盖金额、日期、状态、跨月、存储损坏和防重复；
- 微信分享、系统弹窗、键盘、安全区和真机视觉标为开发者工具/真机验证项。

## 10. 明确不做

登录/授权、服务端、云开发、跨设备同步、多账户、自定义分类管理、完整财务报表、可配置仪表盘、账单导入、支付、AI 建议、理财建议、广告、会员、排行榜、复杂动画、模块自由排序、引导页、多语言、后台管理。

## 11. 验收摘要

必须通过原始提示词 10 组用例，并新增：好友分享菜单、朋友圈引导、分享路径隐私、分享进入数据隔离、读取/保存失败、防重复提交、页面层无缓存 API。
