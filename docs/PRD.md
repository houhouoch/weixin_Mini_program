# PRD：今天还能花（微信小程序 MVP）

- 文档状态：V2.0 预算周期与主动提醒已实现并上传开发版本
- 版本：2.0
- 日期：2026-08-10
- 产品形态：微信原生小程序，单页，本地存储

## 1. 产品概述

“今天还能花”帮助刚工作 1–5 年、收入相对固定但没有稳定预算习惯的年轻上班族，在准备发生一笔可选消费前，用几秒钟确认：

> 今天还可以放心花 ¥XX.XX。

产品不试图替代专业财务软件或提供理财建议，只验证一个最小闭环：设置固定月收入与预算 → 查看今日安全额度 → 记录支出或额外收入 → 额度立即更新 → 次日继续回来查看。

## 2. 产品目标与成功信号

### 2.1 MVP 目标

1. 用户能在 2 分钟内完成首次设置；
2. 用户能在 15 秒内记录金额、消费分类和可选用途；
3. 用户理解主金额与三个辅助指标的关系；
4. 用户愿意跨天再次打开；
5. 分享不会泄露身份和逐笔消费数据。
6. 用户无需进入复杂报表，就能比较今天、昨天、前天以及日/月/年消费趋势；
7. 用户可以选择自己喜欢的页面气质，同时超支和警示仍保持一致且可读。
8. 首页除核心余额外可按需折叠，减少首次滚动长度；
9. 用户可按日期回看真实逐笔明细，并修改或删除当前月及归档记录中的错误。
10. 用户可将全部真实逐笔记录导出为 Excel，并在微信文档页面转发或使用系统提供的保存能力。
11. 用户可主动选择微信官方导出的账单文件，在本机预览、去重并确认导入跨月支出。
12. 有外快、奖金等非固定收入的用户可以逐笔记录收入，并明确看到其增加本月可用额度。
13. 用户可指定开始日期和结束日期，直接查看该时间段的支出总额、日均、笔数、主要分类和趋势。
14. 用户能从自定义统计结果继续查看分类和逐笔支出，并直接纠正异常记录。
15. 用户误导入账单时可按导入批次撤销，换机或清理前可导出并恢复完整本地数据。
16. 用户可按发薪日定义预算周期，不再被自然月 1 日强制切断。
17. 用户可拆分固定支出并保存常用记账模板，减少重复输入。
18. 用户可在日回看中看到本周与上周同期的轻量总结。

### 2.2 本地事件信号

预留统一 `trackEvent()`：

- `app_open`
- `transaction_saved`
- `result_viewed`
- `share_friend`
- `share_timeline_guide`
- `share_entry_open`
- `ledger_export`
- `bill_import`
- `data_backup`

MVP 不接服务端，事件仅走可替换的空实现/本地调试输出。事件 payload 只能包含页面状态、入口、布尔值和计数区间，不得包含逐笔金额、预算金额、OPENID 或身份信息。

## 3. 用户与核心场景

### 3.1 目标用户

- 刚工作 1–5 年的年轻上班族；
- 知道余额，但不知道余额中有多少可以自由花；
- 不愿学习复杂记账或预算体系；
- 在外卖、聚餐、购物、娱乐前需要快速判断。
- 除固定工资外，还可能有兼职、奖金、报销、红包等不定期收入。

### 3.2 核心任务

1. 首次设置收入、固定支出、储蓄目标与启用前已花；
2. 查看“今天还能花”；
3. 选择消费分类、填写可选用途和金额并记一笔；
4. 查看或删除最近 5 笔；
5. 修改或重置本月设置；
6. 跨天/跨月后继续得到正确结果；
7. 向好友或朋友圈分享不含隐私的产品结果摘要。
8. 快速查看日/月/年消费回顾；
9. 选择预设主题，或安全地微调主色与背景温度。
10. 折叠非核心模块，按日期查看并纠正历史明细。
11. 导出全部本地真实流水为 Excel，预览后转发或保存。
12. 从微信会话选择已解压的微信支付账单，确认新增、重复和跳过项后导入。
13. 在“支出 / 收入”间切换，记录额外收入来源并在历史与 Excel 中区分收支。
14. 在消费回看中选择自定义起止日期，统计一段时间内的真实支出。
15. 从自定义统计继续查看分类构成与区间流水，并修改或删除错误记录。
16. 撤销最近的账单导入批次；生成、转发或恢复完整本地备份。
17. 设置每月预算周期起始日和固定支出明细。
18. 保存并一键使用早餐、地铁、咖啡等常用记账模板。
19. 查看本周支出、上周同期、主要分类和增长最多分类。
20. 在设置中查看微信后台配置的正式隐私保护指引。

## 4. 功能范围

### 4.1 首次预算设置

在首页底部抽屉中填写：本月收入、固定支出、储蓄目标、开始使用前已花。字段均为人民币元，除收入必须大于 0 外允许 0，不允许负数，最多两位小数。若今天是 1 日，历史已花默认 0。

设置中的“本月收入”表示用户预计的固定收入基线。保存前必须同时满足：

- `fixedExpense <= income`；
- `fixedExpense + savingGoal <= income + recordedAdditionalIncome`；
- `fixedExpense + historicalSpentBeforeTracking + sum(recordedExpenses) <= income + recordedAdditionalIncome`。

关联错误就近显示在可修正字段下，并告知“最多可填”或“收入至少需要”。上述规则用于防止设置自相矛盾；新增真实消费时不因预算不足而拒绝保存，超出后进入超支预警。

抽屉必须解释“开始使用前已花”不包含固定支出，也不包含小程序内记录；底部显示“数据只保存在当前设备中，不会上传”。设置合法后才能保存。

### 4.2 核心结果

首页核心卡展示：

- 标题“今天还能花”；
- 超大金额 `¥XX.XX`；
- 当前状态文案；
- 今日建议额度、今日已花、本月剩余可用。

设置未完成或读取失败时不得显示伪造金额。

### 4.3 快速记录收支

现有“快速记一笔”增加文字明确的“支出 / 收入”分段入口。支出分类为餐饮、交通、购物、日用、娱乐、医疗、人情、其他；收入分类为外快、奖金、工资、报销、转入、红包、退款、其他收入。收入模式持续显示“设置中的本月收入无需重复记录”，避免固定工资被重复计入。

支出可填写用途，收入可填写来源；两者最多 20 个字符且允许留空。收入保存后增加当月可用额度，但不增加“今天已花”、消费趋势或消费分类排行。控件最小触控高度为 88rpx，当前类型同时用文字、选中背景和后续金额正负号表达，不只依赖颜色。

点击后进入保存中并锁定重复提交；只有本地持久化成功后才清空用途和金额、保留最近使用分类、收起键盘、刷新金额并显示成功反馈。

非法输入包括：空、0、负号、字母、多个小数点、超过两位小数、超过 `999999.99` 元。

### 4.4 最近记录、修改与删除

历史明细包含收支类型、分类、用途/来源、本地时间、金额和删除入口。收入显示“+ ¥”，支出显示“- ¥”，所选日期同时显示收入合计与支出合计。用途或来源为空时显示分类名称；删除前说明将重新计算本月额度。

> 删除这笔 ¥XX.XX 的消费记录？删除后预算会重新计算。

每条记录同时提供“修改”和“删除”。修改使用底部抽屉回填收支类型、分类、用途/来源、金额和交易日期，并允许纠正误选的收支类型；日期只允许在该记录原月份内调整。只有本地持久化成功后才关闭抽屉并刷新余额、回看和明细。

删除成功后立即刷新；没有记录时展示轻量空状态。当前月记录的修改或删除会重新计算今日额度；归档记录的修改或删除只更新对应历史回看，不改变当前月预算。

### 4.5 修改与重置

右上角设置入口打开同一抽屉并回填当前值。保存设置时保留已有记录并执行 4.1 的关联校验。为兼容旧版已保存的矛盾设置，结果层仍能安全展示“无可用额度”，但下次修改必须修正关系后才能保存。

重置位于次要区域，确认文案：

> 将删除本月设置和所有消费记录，且无法恢复。确定继续吗？

设置抽屉的数据本地说明下方提供“隐私保护指引”入口，通过 `wx.openPrivacyContract` 打开微信后台配置并审核生效的正式指引。产品不再维护内容重复的自建协议页面；接口不可用或打开失败时给出明确提示，不影响手动记账。

### 4.6 跨天与跨月

页面 `onShow` 时按设备本地日期刷新。跨天保留记录并重新归类今日消费。检测到新月份时提示沿用设置或重新设置：沿用只保留收入、固定支出、储蓄目标，清空历史基线和交易，新启用日期设为当天。

### 4.7 分享

- 开启好友和朋友圈分享菜单；
- 好友按钮使用微信原生分享能力；
- 朋友圈使用右上角菜单引导；
- 标题使用“预算人格 + 使用天数 + 记录笔数 + 本月累计花费”的摘要；
- 路径只带 `from=share`；不携带交易、金额明细、OPENID 或身份信息；
- 分享进入者只读取自己的本地存储，没有数据时看到“开始我的收支记录”。

### 4.8 语义化余额状态

首页主视觉必须提供四种可辨识状态，不能只把同一张卡片换颜色：

1. 正常：森林绿，突出“今天还能花”；
2. 额度将尽：琥珀黄，显示剩余金额与“下一笔先想一想”；
3. 今日超额：珊瑚红，明确显示“已超 ¥XX.XX”，不得只显示 `¥0`；
4. 本月超支：使用更深的危险色，并解释本月已超出的金额与后续影响。

标题、金额/状态文案、进度条和状态标签必须同步变化，并提供 150–240ms 的连续过渡。危险状态仍保留原消费插画作为品牌背景，但通过文字承载层保证可读性。

### 4.9 消费回看

首页增加轻量“消费回看”模块，使用 `日｜月｜年｜自定义` 分段切换，不新增 tabBar 或独立报表页。

- 日：展示今天、昨天、前天金额，最近 7 天柱状趋势和本周消费最高分类；
- 月：展示本月总额、日均、最高消费日、最高分类和按周/日期趋势；
- 年：展示全年总额、月均、最高月份和 12 个月趋势；
- 自定义：通过两个原生日期选择器设置开始日期和结束日期，起止日均计入；展示区间支出总额、按自然日计算的日均、支出笔数、最高分类和最多 7 段的轻量趋势；
- 点击某日或月份时，后续可用底部抽屉查看明细，但不得新增页面层级。

自定义时间段只统计具有真实交易日期的支出，不统计收入，也不把“启用前已花”汇总伪造成某日支出。结束日期不得晚于今天，开始日期不得晚于结束日期；页面选择时自动保持有效区间，领域层仍必须拒绝非法参数。没有支出时展示 `¥0`、`0笔` 和明确空状态，不把读取成功误报为错误。

自定义统计结果同时显示全部支出分类的金额、笔数和区间占比。用户可查看全部区间流水或点击分类只看对应流水；明细沿用既有修改、删除与失败恢复能力，不新增页面。切换日期或分类时不得展示上一范围的旧结果。

图表只服务于“比较和回看”，不提供资产负债、预算预测、投资建议或可配置仪表盘。

### 4.10 主题工作室

设置抽屉增加主题入口，首版提供 6 套预设：暖森林、海岸蓝、日落珊瑚、午夜、青柠、黑白。用户可进一步微调主色调、背景温度和亮度，界面实时预览并提供恢复默认。

系统根据用户选择派生正文、表面和边框颜色，保证基础对比度。警示黄、超支红和对应文字对比度始终由系统锁定，不跟随用户主题变化。模块排序和自由配色器不进入本轮范围。

### 4.11 折叠首页与日期明细

核心结果与预算轨道始终展开。消费回看、快速记一笔、记录与历史使用三个独立折叠区，默认收起；标题行显示模块名称、简短摘要和“展开/收起”文字，不依赖箭头方向或颜色表达状态。展开/收起不得触发水平手势，触控区域至少 88rpx，动效为 150–240ms，并尊重减少动态效果设置。

“记录与历史”展开后提供原生日期选择器，默认今天，最大日期为今天。选择日期后读取当前月或最多 36 个月归档中的真实逐笔记录，展示当日总额、笔数、分类、用途、时间和金额。没有明细时显示明确空状态；启用前汇总没有逐笔日期，因此不得出现在日期明细中。

### 4.12 Excel 流水导出

“记录与历史”展开后提供“导出并打开 Excel”。文件必须是无第三方依赖生成的真实 `.xlsx`，包含当前月和最多 36 个月归档中的全部真实逐笔记录。每行展示日期、时间、收支、分类、用途/来源、金额和数据来源，顶部显示导出时间、笔数、支出合计与收入合计。

启用前汇总因没有日期、分类和用途，不伪造成流水，而在文件说明中明确告知。文件只写入 `wx.env.USER_DATA_PATH`，不上传，不含 OPENID、昵称、头像或其他身份信息。小程序使用 `wx.openDocument({ showMenu: true })` 打开，并提供 `wx.shareFileMessage` 直接转发入口；具体保存选项以微信客户端与设备系统菜单为准。

### 4.13 微信/支付宝账单文件导入

当前版本不调用个人钱包接口。微信账单先用邮件密码解压，再把 `.xlsx` 或 `.csv` 发送到任意微信会话；支付宝直接导出交易明细 `.csv` 并发送到微信会话。两种平台共用一个 `wx.chooseMessageFile` 入口，小程序根据表头自动识别平台，只在本机读取。

微信解析器动态寻找“交易时间、收/支、金额”表头，交易时间兼容文本和 Excel 数值日期序列，只导入有效支出。支付宝 CSV 使用 GB18030 或 UTF-8 解码并动态发现表头；`交易成功`支出与`等待确认收货`支出视为已占用资金，`交易成功`收入作为额外收入。`交易关闭`不导入；还款和“信用借还”是结清已有债务，不是新消费；投资理财和其他“不计收支”也不进入日常收支。

支付宝退款采用配对口径：若`退款成功`与同订单、同金额的`交易关闭`原记录匹配，认定为全额退款并成对跳过，避免凭空增加收入；若原交易仍为`交易成功`且退款金额较小，认定为部分退款，保留原支出并将退款记为`income_refund`；找不到原交易的消费退款也按退款收入导入，覆盖原消费位于导出范围之外的情况。投资理财退款仍跳过。

预览显示平台、文件名、日期范围、新增/重复笔数、支出与收入/退款合计，以及还款、全额退款抵消、不计收支、无效状态和超期等跳过原因。用户确认后才通过 `addTransaction({ action: 'import' })` 写入。

重复识别使用交易单号、时间、金额、状态等临时字段生成不含原文的本地双哈希指纹。原交易单号、账号、昵称和身份字段不写入本地数据，不进入埋点或分享。导入后的记录与手动记录一样可以按日期查看、修改、删除和导出；Excel 数据来源标记为“微信支付导入”或“支付宝导入”。

### 4.14 导入批次撤销

每次确认导入都生成不含平台订单号的本地批次 ID，并附加到本次实际新增的交易。记录与历史区显示最近 5 个仍有记录的导入批次，包括平台、导入时间、日期范围和剩余笔数。用户二次确认后可一次撤销该批次尚存的全部记录，当前月预算、历史回看和区间统计立即刷新。

旧版本已经导入但没有批次 ID 的交易仍可逐笔修改或删除，不伪造成可批量撤销；已经手动删除的批次记录不会恢复。

### 4.15 完整本地备份与恢复

用户可生成 `.json` 完整备份，内容包括当前月预算、当前与最多 36 个月历史逐笔记录、导入批次元数据和主题设置。文件只写入小程序用户目录，可通过微信转发，PC 端可保存到磁盘；不得加入 OPENID、昵称、头像或平台交易单号原文。

恢复使用 `wx.chooseMessageFile` 选择本产品备份文件。系统先校验文件类型、格式版本、数据 schema、预算/交易字段和主题安全范围，再展示备份时间、月份范围和流水笔数。用户二次确认后整体替换当前本地数据；校验或持久化失败时保留原数据，不得出现半恢复状态。Excel 继续只用于查看，不作为恢复文件。

### 4.16 负余额语义

当本月剩余额度小于 0 时，预算轨道右侧显示“本月超支 ¥XX.XX”，金额取超支绝对值；不得继续显示“本月可用 ¥-XX.XX”。正常与零余额仍显示“本月可用”。

### 4.17 多平台账单接入路线图

银行文件适配保留为后续路线图。银行直连需逐行合作、用户授权、合规评估与服务端，不属于当前纯本地 MVP；在独立样本、格式、去重和异常验收完成前，不新增适配器，也不伪称可以通过商户对账 API 读取普通用户个人钱包。

### 4.18 自定义预算周期

预算设置增加“每月预算从几号开始”，范围为 1–28 日，默认 1 日。选择 15 日时，一个完整周期为当月 15 日至下月 14 日，首尾日均计入。限制到 28 日是为了避免 29–31 日在短月份中的不确定回退。

自然月仍作为本地交易归档和月/年回看的存储边界；核心余额、固定收入、额外收入、启用前已花和超支状态按当前预算周期聚合。跨自然月只归档工作集，不结束预算周期；到达新预算周期时沿用预算金额和固定支出明细，启用前已花归零。首次设置或修改起始日后，当前周期起点按设备日期回推。

页面明确显示“本月”或“本周期”：起始日为 1 时沿用“本月”，否则显示周期日期和“本周期可用/本周期超支”。修改周期必须重新校验当前周期内真实收支；不得删除、移动或伪造交易。

### 4.19 固定支出明细

设置抽屉保留固定支出总额，并允许添加最多 12 项明细，每项包含名称（1–12 个字符）和金额。明细合计不得超过固定支出总额；小于总额的差额按“其他固定支出”解释，避免用户必须一次拆完。名称去除首尾空白，空行不保存。

固定支出明细只用于解释预算扣减，不生成逐笔流水，也不重复进入消费回看或 Excel。修改总额导致明细合计超出时必须就近阻止保存。

### 4.20 常用记账模板

快速记账区支持保存最多 8 个本地模板，字段为收支方向、分类、用途/来源和金额。模板标题优先使用用途/来源，空时使用分类名。点击模板即以当前时间调用既有 `addTransaction({ action: 'create' })` 记一笔；保存中禁用全部模板，成功与失败沿用快速记账反馈。

用户可把当前合法输入保存为模板，并可删除模板。模板不包含日期、平台订单号或身份数据；完整 JSON 备份包含模板，Excel 不导出模板。

### 4.21 周总结

日回看增加本周总结：按周一至今天统计真实支出，并与上周相同星期跨度比较，避免周中拿不完整本周与完整上周比较。展示本周支出、上周同期、金额/百分比变化、主要支出分类和较上周增加最多的分类；无可比基数时使用“上周同期无支出”的中性文案。

周总结不统计收入、固定支出或启用前汇总，不提供理财结论、预测或羞辱性文案。

### 4.22 分类预算提醒（已移除）

根据 2026-08-10 的用户反馈，设置抽屉不再展示分类预算输入，首页也不再显示分类预算提醒。schema 5 中既有 `categoryBudgets` 字段仅为旧数据和备份兼容保留；页面保存预算时写为空数组，不参与当前交互或展示。

## 5. 计算口径

全部金额使用整数分。

```text
monthlyFlexibleBudget = fixedIncome + sum(recordedIncome) - fixedExpense - savingGoal
spentBeforeToday = historicalSpentBeforeTracking + recordedSpentBeforeToday
todaySuggestedBudget = floor(max(monthlyFlexibleBudget - spentBeforeToday, 0) / daysRemainingIncludingToday)
todayRemaining = max(todaySuggestedBudget - todaySpent, 0)
monthlyRemaining = monthlyFlexibleBudget - historicalSpentBeforeTracking - sum(expenseRecords)
```

其中 `recordedIncome`、`expenseRecords`、剩余天数和启用前已花均限定在当前预算周期。自定义周期的剩余天数为今天到周期结束日（含今天）；自然月回看仍按日历月统计。

状态优先级：

1. `monthlyFlexibleBudget <= 0`：固定支出和储蓄目标已用完收入；
2. `monthlyRemaining < 0`：本月已超支；
3. `todaySpent > todaySuggestedBudget`：今日已超额；
4. `0 < todayRemaining <= floor(todaySuggestedBudget * 30 / 100)`：额度将尽；
5. 其他：正常。

当月剩余可以为负；今日还能花最低为 0。剩余天数含今天，最小为 1。

### 6.1 V1.2 历史归档

`schemaVersion: 3` 将“当前月工作集”和“只读历史归档”分开保存。跨月沿用或重设时先归档旧月，最多保留 36 个月；同一月份重复归档时覆盖该月副本，避免重复计算。重置当前月只清空当前工作集，不删除往月归档。

`historicalSpentBeforeTrackingCents` 只有汇总金额，没有日期和分类，不能反推旧日期趋势或分类占比。因此它只计入对应期间总额，并通过范围文案明确说明；趋势柱、最高日/月和分类排行只读取真实逐笔记录。schema 3 迁移不删除当前记录。

### 6.2 V1.6 收支方向

`schemaVersion: 4` 为每笔流水增加 `direction`。`expense` 参与今日已花、历史消费与超支判断；`income` 仅作为实际新增收入增加发生月份的可用额度。支出和收入分类不得交叉使用，微信账单文件导入仍只导入有效支出。

### 6.3 V2.0 预算周期与快捷配置

`schemaVersion: 5` 在预算中增加周期起始日、当前周期起点、固定支出明细和分类预算，在根状态增加常用模板。自然月历史结构不变，保证既有账单导入、日期纠错和月/年回看兼容；跨自然月归档时，自定义周期的启用前汇总不重复写入历史月。

## 7. 页面与交互结构

单页自上而下：安全区顶部与设置入口 → 插画化核心结果 → 预算进度 → 可折叠消费回看（含周总结）→ 可折叠快速记账（含常用模板）→ 可折叠记录、日期历史、账单导入与 Excel 导出 → 轻量分享入口。预算周期和固定支出明细仍在同一设置抽屉；不新增页面或 tabBar。

必须覆盖：读取中、首次空、记录空、保存中、成功、读取失败、保存失败、防重复、确认弹窗和跨月选择。

## 8. 视觉原则

- 使用原创编辑插画作为首页主视觉，建立与日常消费相关的品牌记忆；
- 暖奶油色纸张背景，森林绿、珊瑚橙和黄油黄作为主要色块；
- 内容通过纸带、色块和排版分区，不连续堆叠同形白色圆角卡片；
- 红色仅用于错误和超支；警示黄和超支红不受用户主题覆盖；
- 微信系统字体，数字使用稳定的系统无衬线字体；
- 预算进度只使用一条可读的比例轨道；消费回看仅使用轻量柱状趋势，不引入复杂财务图表；
- 主金额是唯一最高视觉层级；
- 触控目标至少 44 CSS px 等效尺寸；
- 窄屏、刘海区、底部手势区和超长金额均不遮挡。

## 9. 非功能要求

- 无第三方运行时依赖；
- 数据接口均返回 Promise；
- 页面不得直接访问缓存；
- 保存失败不得假装成功；
- 自动化测试覆盖金额、预算关联约束、自定义周期跨月、固定支出明细、常用模板、周同比口径、日期、状态、归档、schema 迁移、日/月/年/自定义区间聚合与下钻、导入批次撤销、完整备份恢复、XLSX 生成与解析、账单过滤与去重、主题安全范围、存储损坏和防重复；
- 微信分享、系统弹窗、键盘、安全区和真机视觉标为开发者工具/真机验证项。

## 10. 明确不做

登录/授权、服务端、云开发、跨设备同步、多账户、自定义分类管理、固定支出自动生成流水、复杂周期（每周/不规则/29–31 日）、完整财务报表、可配置仪表盘、个人钱包/支付宝/银行直接 API 同步、银行账单文件适配、加密 ZIP 在小程序内解密、支付、AI 建议、理财建议、广告、会员、排行榜、复杂动画、模块自由排序、引导页、多语言、后台管理。

## 11. 验收摘要

必须通过原始提示词 10 组用例，并新增：好友分享菜单、朋友圈引导、分享路径隐私、分享进入数据隔离、读取/保存失败、防重复提交、页面层无缓存 API。
