# SDD Specification 001：今天还能花

## 用户故事与可验收场景

### US1 首次设置（P0）

作为首次用户，我要填写四项预算数据，以便得到真实的今日额度。

- Given 本地无有效数据，When 打开首页，Then 显示设置抽屉且不显示伪造结果。
- Given 四项输入合法，When 保存成功，Then 关闭抽屉并显示重新计算的结果。
- Given 本地写入失败，When 保存，Then 保留输入并显示“保存失败，请重试”。

### US2 查看今日额度（P0）

作为准备消费的用户，我要一眼看到安全金额和原因。

- Given 有有效预算，When 打开或回到前台，Then 按当前本地日期刷新全部金额。
- Given 预算为零、超支、今日超额、额度将尽或正常，Then 按规定优先级显示对应文案。

### US3 快速记账（P0）

作为消费后的用户，我要记录消费分类、可选用途和金额，并立刻看到新额度。

- 合法金额只生成一条记录；连续点击不得重复。
- 分类必须来自固定白名单；用途可为空，非空时最多 20 个字符。
- 只有持久化成功后才清空输入和显示成功。
- 非法金额不调用数据写入。

### US4 最近记录与删除（P0）

作为用户，我要查看最近 5 笔并可纠错删除。

- 列表按时间倒序，最多展示 5 条，并显示分类、用途、时间和金额。
- 删除需要二次确认，成功后立即刷新。

### US5 修改、重置与月份切换（P0）

- 修改预算保留本月交易。
- 重置需明确确认并删除本月设置和交易。
- 跨月不混用数据；可沿用三项预算或重新设置。

### US6 隐私安全分享（P1）

- 好友分享和朋友圈菜单已开启。
- 好友按钮使用 `open-type="share"`；朋友圈提供右上角菜单引导。
- 分享标题包含预算人格、使用天数、记录笔数和本月累计花费摘要。
- 分享路径和 query 不包含金额、交易、OPENID 或身份信息。
- 分享进入只显示接收者设备自己的数据。

### US7 余额状态转换（P0）

- 正常、额度将尽、今日超额、本月超支均有独立标题、金额/状态文案、进度和标签。
- 今日超额显示实际超出金额，不以 `¥0` 代替警示。
- 状态不依赖颜色即可理解，颜色变化维持可读对比。

### US8 日/月/年消费回看（P1）

- 首页同一模块提供 `日｜月｜年` 切换，不新增页面或 tabBar。
- 日视图包含今天/昨天/前天、最近 7 天趋势和最高分类。
- 月视图包含总额、日均、最高日、最高分类和轻量趋势。
- 年视图只基于真实历史归档生成；缺失历史时说明数据范围，不伪造趋势。

### US9 主题工作室（P1）

- 用户可在 6 套预设主题间切换并实时预览。
- 高级微调只开放主色、背景温度和亮度等安全参数。
- 警示黄、超支红和可读文字色由系统锁定；可恢复默认。

### US10 折叠、日期回顾与交易纠错（P0）

- 核心余额和预算轨道常驻；消费回看、快速记账、记录与历史默认折叠且可独立展开。
- 用户可通过原生日期选择器查看当前月和最多 36 个月归档中的真实逐笔明细。
- 当前月与归档记录均可修改金额、分类、用途和原月份内日期，也可二次确认后删除。
- 修改持久化成功后刷新余额、聚合和所选日期明细；失败时保留编辑内容并提示。

### US11 预算关联约束（P0）

- 本月收入必须大于 0；固定支出不得超过收入。
- 固定支出与储蓄目标合计不得超过收入。
- 固定支出、启用前已花与已记录消费合计不得超过收入；错误告知可填上限或所需最低收入。
- 交易是事实记录，即使导致超支也不拒绝新增，而是刷新为超支预警。

### US12 Excel 流水导出（P1）

- 用户可在“记录与历史”折叠区中导出当前月和归档月的全部真实逐笔记录。
- 文件是可被 Excel 读取的 `.xlsx`，包含日期、时间、分类、用途、金额和数据来源。
- 启用前汇总不伪造成逐笔流水；文件不含 OPENID 或身份信息。
- 生成后通过 `wx.openDocument({ showMenu: true })` 预览，并可用 `wx.shareFileMessage` 直接转发。

## 功能需求

- FR-001：所有金额以分为整数保存与计算。
- FR-002：页面仅一页，无 tabBar。
- FR-003：页面不得直接调用缓存 API。
- FR-004：交易模块仅公开 Promise API `addTransaction`、`listTransactions`。
- FR-005：支持添加与删除交易命令，保证同一命令 ID 幂等。
- FR-006：统一 `trackEvent`，禁止金额和身份字段。
- FR-007：支持读取中、空、成功、读取失败、保存中、保存失败、防重复状态。
- FR-008：实现本地日期的跨天与闰年/月末计算。
- FR-009：实现跨月沿用与重新设置。
- FR-010：实现微信好友/朋友圈分享生命周期。
- FR-011：交易保存分类 ID 和可选用途，旧版金额记录可无损迁移。
- FR-012：页面提供 8 个固定分类快捷选择，不提供分类管理页。
- FR-013：用途、分类和逐笔金额不得进入埋点或分享参数。
- FR-014：语义状态必须同时驱动标题、状态金额/说明、进度与标签，不能只切换颜色。
- FR-015：消费回看在单页内提供日/月/年聚合，图表数据必须来自本地真实记录。
- FR-016：年度趋势依赖带日期和分类的历史归档；汇总基线不得被拆分或估算成历史记录。
- FR-017：主题预设和安全微调不得覆盖 warning/danger 语义色。
- FR-018：主题设置、历史归档与现有 schema 迁移均通过 Promise 服务访问，页面不得直接读写缓存。
- FR-019：三个非核心模块必须独立折叠，折叠状态同时以文字和布局表达。
- FR-020：`listTransactions({ dateKey })` 可读取当前工作集和历史归档中的指定日期真实明细。
- FR-021：`addTransaction({ action: 'update' | 'delete' })` 可纠正当前或归档记录，并保持命令幂等。
- FR-022：修改日期不得跨越记录原月份；启用前汇总不得伪造成日期明细。
- FR-023：预算保存同时校验收入、固定支出、储蓄目标、启用前已花与已记录消费的关联约束。
- FR-024：页面与预算服务必须共用同一纯函数校验，避免绕过页面保存无效数据。
- FR-025：导出服务只读本地状态，生成无压缩的标准 XLSX ZIP 包并写入小程序用户目录。
- FR-026：文件导出与转发不得改变本地交易，不得上传文件或加入身份字段。

## 约束

- 原生 JavaScript/WXML/WXSS/JSON；无运行时第三方依赖。
- 无服务端、云开发、登录授权和敏感权限。
- 单笔上限 99,999,999 分；设置单项上限 999,999,999 分。
