# SDD Specification 001：今天还能花

## 用户故事与可验收场景

### US1 首次设置（P0）

作为首次用户，我可以填写预算数据，也可以使用明示的示例预算先看完整页面。

- Given 本地无有效数据，When 打开首页，Then 显示设置抽屉且不显示伪造结果。
- Given 四项输入合法，When 保存成功，Then 关闭抽屉并显示重新计算的结果。
- Given 用户暂时不想填写，When 点击“先看看”，Then 以收入 8000、固定支出 800、储蓄目标 2000、每月 1 日起始的示例预算保存并进入首页，不生成任何流水。
- Given 本地写入失败，When 保存，Then 保留输入并显示“保存失败，请重试”。

### US2 查看今日额度（P0）

作为准备消费的用户，我要一眼看到安全金额和原因。

- Given 有有效预算，When 打开或回到前台，Then 按当前本地日期刷新全部金额。
- Given 预算为零、超支、今日超额、额度将尽或正常，Then 按规定优先级显示对应文案。

### US3 快速记账（P0）

作为有收支变动的用户，我要记录支出或额外收入，并立刻看到新额度。

- 合法金额只生成一条记录；连续点击不得重复。
- 分类必须来自固定白名单；用途可为空，非空时最多 20 个字符。
- 只有持久化成功后才清空输入和显示成功。
- 非法金额不调用数据写入。
- 支出与收入使用独立分类白名单；额外收入增加可用额度但不计入消费回看。

### US4 最近记录与删除（P0）

作为用户，我要查看最近 5 笔并可纠错删除。

- 列表按时间倒序，最多展示 5 条，并显示分类、用途、时间和金额。
- 删除需要二次确认，成功后立即刷新。

### US5 修改、重置与月份切换（P0）

- 修改预算保留本月交易。
- 重置需明确确认并删除本月设置和交易。
- 跨月不混用数据；可沿用三项预算或重新设置。

### US6 隐私安全分享（P1）

- 好友分享和朋友圈菜单已开启。
- 好友按钮使用 `open-type="share"`；朋友圈提供右上角菜单引导。
- 分享标题包含预算人格、使用天数、记录笔数和本月累计花费摘要。
- 分享路径和 query 不包含金额、交易、OPENID 或身份信息。
- 分享进入只显示接收者设备自己的数据。

### US7 余额状态转换（P0）

- 正常、额度将尽、今日超额、本月超支均有独立标题、金额/状态文案、进度和标签。
- 今日超额显示实际超出金额，不以 `¥0` 代替警示。
- 状态不依赖颜色即可理解，颜色变化维持可读对比。

### US8 日/月/年与自定义时间段消费回看（P1）

- 首页同一模块提供 `日｜月｜年｜自定义` 切换，不新增页面或 tabBar。
- 日视图包含今天/昨天/前天、最近 7 天趋势和最高分类。
- 月视图包含总额、日均、最高日、最高分类和轻量趋势。
- 年视图只基于真实历史归档生成；缺失历史时说明数据范围，不伪造趋势。
- 自定义视图使用起止日期（含首尾日）统计真实支出总额、自然日日均、支出笔数、最高分类和轻量趋势；收入与启用前汇总均不计入。

### US9 主题工作室（P1）

- 用户可在 6 套预设主题间切换并实时预览。
- 高级微调只开放主色、背景温度和亮度等安全参数。
- 警示黄、超支红和可读文字色由系统锁定；可恢复默认。

### US10 折叠、日期回顾与交易纠错（P0）

- 核心余额和预算轨道常驻；消费回看、快速记账、记录与历史默认折叠且可独立展开。
- 用户可通过原生日期选择器查看当前月和最多 36 个月归档中的真实逐笔明细。
- 当前月与归档记录均可修改金额、分类、用途和原月份内日期，也可二次确认后删除。
- 修改持久化成功后刷新余额、聚合和所选日期明细；失败时保留编辑内容并提示。

### US11 预算关联约束（P0）

- 本月收入必须大于 0；固定支出不得超过收入。
- 固定支出与储蓄目标合计不得超过固定月收入与已记录额外收入之和。
- 固定支出与已记录支出合计不得超过该收入合计；错误告知所需最低收入。
- 交易是事实记录，即使导致超支也不拒绝新增，而是刷新为超支预警。
- 设置页不再提供启用前已花输入；新保存的预算将兼容字段写为 0。

### US12 Excel 流水导出（P1）

- 用户可在“记录与历史”折叠区中导出当前月和归档月的全部真实逐笔记录。
- 文件是可被 Excel 读取的 `.xlsx`，包含日期、时间、收支、分类、用途/来源、金额和数据来源。
- 启用前汇总不伪造成逐笔流水；文件不含 OPENID 或身份信息。
- 生成后通过 `wx.openDocument({ showMenu: true })` 预览，并可用 `wx.shareFileMessage` 直接转发。

### US13 微信支付账单文件导入（P0）

- 用户从微信会话选择已解压的官方 `.xlsx` 或 `.csv` 文件；加密 ZIP 不在小程序内解密。
- 解析前不写入；预览显示日期范围、新增、重复、跳过和新增支出合计。
- 只导入最近 36 个月至当前时刻的有效支出；收入、不计收支、退款、撤销、关闭和无效行跳过。
- 文件内和已有流水均按稳定本地指纹去重；用户确认后才批量写入当前月或历史归档。
- 原交易单号和身份字段不落盘、不埋点、不分享；导入后可以按日期修改或删除。

### US14 额外收入记录（P0）

- “快速记一笔”提供文字明确的“支出 / 收入”切换，默认支出。
- 收入用于外快、奖金等实际新增收入；页面提示设置中的本月固定收入无需重复记录。
- 收入保存后增加发生月份的可用额度，不增加今天已花、消费趋势或消费分类排行。
- 历史和 Excel 同时展示收支方向；误选方向可在原月份内修改。

### US15 统计下钻与纠错（P0）

- 自定义时间段统计展示全部支出分类的金额、笔数和占比。
- 用户可展开全部区间流水，或点击分类只看对应流水。
- 区间流水沿用修改、删除和刷新能力；收入与启用前汇总不得出现。

### US16 导入批次撤销（P0）

- 每次新确认导入生成本地批次 ID，只关联本次实际新增记录。
- 最近 5 个仍有记录的批次显示平台、导入时间、日期范围和剩余笔数。
- 二次确认后一次删除该批次剩余记录；操作幂等并刷新预算、回看和历史。

### US17 完整备份恢复与超支语义（P0）

- 完整备份使用本产品 JSON 格式，包含预算、当前/归档流水、批次和主题，不含身份字段或原平台交易单号。
- 恢复前校验并预览，二次确认后整体替换；失败保持原数据。
- 月度剩余额度为负时显示“本月超支 ¥绝对值”，不得显示“本月可用 ¥负数”。

### US18 自定义预算周期（P0）

- 用户可选择每月 1–28 日作为预算周期起始日；15 日对应 15 日至次月 14 日。
- 周期提示将起始日解释为工资或父母生活费等稳定收入到账日。
- 核心额度按当前周期统计；月/年回看仍按自然月。
- 跨自然月只归档交易，跨预算周期沿用设置并将启用前已花归零。

### US19 固定支出明细（P0）

- “固定收入”和“固定支出”以更大字号、主题色和独立分组标题呈现。
- 固定收入与固定支出标题都不追加“每个预算周期”。
- 用户可在“直接填写”和“明细合计”之间切换；旧数据和首次设置默认直接填写。
- 直接填写模式只展示可编辑总额，不展示固定支出明细；保存时明细为空，不得因隐藏明细阻止保存。
- 明细合计模式将总额显示为只读结果并展示明细；新增、修改和移除后实时累加，本次编辑中切回直接填写恢复切换前的直接填写草稿。
- 仅在明细合计模式下，用户可添加最多 12 条固定支出明细；名称和金额必须完整有效。
- 固定支出明细不生成流水，也不重复改变核心预算公式。
- 分类预算设置和首页提醒不再展示；旧字段仅用于 schema 5 兼容。

### US20 常用记账模板（P0）

- 用户可将当前合法收支输入保存为最多 8 个模板。
- 点击模板以当前时间一键调用既有交易命令；保存中防重复，失败保留模板。
- 模板支持删除并进入完整本地备份。

### US21 周总结（P1）

- 日回看展示周一至今天的支出，与上周相同星期跨度比较。
- 展示主要分类和较上周增加最多分类；不统计收入、固定支出或启用前汇总。

### US22 稳定日额度、语音记账与周期省下（P0）

- 每日建议额度使用扣除固定支出和储蓄目标后的周期可支配预算除以周期总天数，不随月底剩余天数骤增。
- 用户点击麦克风开始或结束语音识别；识别文字进入与手动输入相同的解析和确认流程，确认前不得保存。
- 语音插件、权限或识别不可用时明确提示，并始终保留手动文字输入。
- 首页展示本月或本周期省下金额，并注明已扣除储蓄目标；负值改为“还差”。

### US23 多笔智能核对、照片记账与日历分析（P0）

- 用户可以在一段文字或语音中说多笔消费；本地规则识别中文数字、常见时间和多笔分隔词，再进入可编辑的批量确认层。
- 每笔草稿可单独取消、修改用途、修改金额、修改分类和发生时间；只保存用户最终选中的记录。
- 外币只按页面明示的本地参考汇率生成可修改人民币草稿；不声称为实时汇率。
- 照片记账支持直接拍照或从相册选择，当前无后端版本仅在本机预览并由用户手动核对，不伪造 OCR 结果。
- 本月支出分析默认可见，使用月历显示每日金额，并使用平滑曲线展示每日支出走势。
- 月度分析可在近 36 个月内逐月向前或向后切换；不得进入未来月份，所选月份的日历、指标、趋势和按月账单必须同步更新。
- 用户点击月历中的非未来日期后，必须在月历下方即时看到当天真实支出合计和逐笔用途、分类、时间、金额；空日期显示明确空状态。

## 功能需求

- FR-001：所有金额以分为整数保存与计算。
- FR-002：页面仅一页，无 tabBar。
- FR-003：页面不得直接调用缓存 API。
- FR-004：交易模块仅公开 Promise API `addTransaction`、`listTransactions`。
- FR-005：支持添加与删除交易命令，保证同一命令 ID 幂等。
- FR-006：统一 `trackEvent`，禁止金额和身份字段。
- FR-007：支持读取中、空、成功、读取失败、保存中、保存失败、防重复状态。
- FR-008：实现本地日期的跨天与闰年/月末计算。
- FR-009：实现跨月沿用与重新设置。
- FR-010：实现微信好友/朋友圈分享生命周期。
- FR-011：交易保存分类 ID 和可选用途，旧版金额记录可无损迁移。
- FR-012：页面提供 8 个固定分类快捷选择，不提供分类管理页。
- FR-013：用途、分类和逐笔金额不得进入埋点或分享参数。
- FR-014：语义状态必须同时驱动标题、状态金额/说明、进度与标签，不能只切换颜色。
- FR-015：消费回看在单页内提供日/月/年/自定义时间段聚合，图表数据必须来自本地真实记录。
- FR-016：年度趋势依赖带日期和分类的历史归档；汇总基线不得被拆分或估算成历史记录。
- FR-017：主题预设和安全微调不得覆盖 warning/danger 语义色。
- FR-018：主题设置、历史归档与现有 schema 迁移均通过 Promise 服务访问，页面不得直接读写缓存。
- FR-019：三个非核心模块必须独立折叠，折叠状态同时以文字和布局表达。
- FR-020：`listTransactions({ dateKey })` 可读取当前工作集和历史归档中的指定日期真实明细。
- FR-021：`addTransaction({ action: 'update' | 'delete' })` 可纠正当前或归档记录，并保持命令幂等。
- FR-022：修改日期不得跨越记录原月份；启用前汇总不得伪造成日期明细。
- FR-023：预算保存同时校验收入、固定支出、储蓄目标与已记录消费的关联约束；页面保存时将旧版启用前汇总写为 0。
- FR-024：页面与预算服务必须共用同一纯函数校验，避免绕过页面保存无效数据。
- FR-025：导出服务只读本地状态，生成无压缩的标准 XLSX ZIP 包并写入小程序用户目录。
- FR-026：文件导出与转发不得改变本地交易，不得上传文件或加入身份字段。
- FR-027：微信与支付宝账单共用 `wx.chooseMessageFile` 入口，按表头自动识别平台；文件读取只通过基础设施边界，页面不得直接访问文件系统管理器。
- FR-028：CSV/XLSX 解析器必须动态发现表头，不依赖固定元数据行数；交易时间兼容文本和 Excel 数值日期序列；XLSX 通过 `readZipEntry` 分别读取工作表和共享文本索引；CSV 兼容 UTF-8 与 GB18030，且不引入运行时依赖。
- FR-029：微信账单只接受有效支出；支付宝接受有效支出与收入，过滤还款、投资理财、不计收支、关闭、无效、未来和超过 36 个月的记录，并返回可解释统计。
- FR-030：`addTransaction({ action: 'import' })` 同时写入当前工作集和历史归档，按稳定 ID 去重；交易模块仍只公开 `addTransaction` 和 `listTransactions`。
- FR-031：交易单号只能参与不含原文的本地指纹，不得保存原文；昵称、身份字段和逐笔金额不得进入埋点。
- FR-032：导入记录在 Excel 中按平台标记“微信支付导入”或“支付宝导入”，并继续支持按日期查看、修改和删除。
- FR-033：交易必须保存 `direction: "expense" | "income"`，支出和收入使用独立分类白名单。
- FR-034：预算公式使用固定收入加逐笔额外收入；所有消费指标只聚合支出。
- FR-035：schema 1/2/3 迁移到 schema 4 时，旧流水必须标记为支出且不丢失金额、日期、分类、用途或历史归档。
- FR-036：历史日期摘要同时展示收入合计和支出合计，金额使用“+ / -”及文字语义，不只依赖颜色。
- FR-037：Excel 增加“收支”列并分别展示支出合计与收入合计。
- FR-038：收入保存、修改、删除沿用现有 Promise API、幂等和失败恢复状态，不增加新的公开交易 API。
- FR-039：支付宝还款/信用借还视为债务结清而非新消费，不能与原消费重复计入支出。
- FR-040：支付宝全额退款若匹配同订单、同金额的关闭原交易，两条均跳过；部分或跨期消费退款作为 `income_refund` 导入；投资理财退款跳过。
- FR-041：支付宝稳定 ID 不保存交易订单号或账号原文；预览和埋点不得携带逐笔金额或身份字段。
- FR-042：自定义时间段的开始与结束日期均计入统计，只聚合支出；收入和无逐笔日期的启用前汇总必须排除。
- FR-043：自定义时间段结束日期不得晚于今天，开始日期不得晚于结束日期；趋势最多分为 7 个连续时间桶，并显示实际数据口径。
- FR-044：`listTransactions({ startDateKey, endDateKey, direction, categoryId })` 返回区间筛选结果，自定义统计分类合计与明细总额必须一致。
- FR-045：导入交易保存本地 `importBatchId` 与导入时间；修改交易不得丢失批次归属，删除后不恢复。
- FR-046：`addTransaction({ action: 'undoImport' })` 按批次删除当前与归档记录并保持命令幂等；交易模块仍只公开 `addTransaction`、`listTransactions`。
- FR-047：完整备份服务只通过状态、主题与文件基础设施边界读写，页面不得直接访问缓存或文件系统管理器。
- FR-048：恢复文件必须校验产品标识、格式版本、当前数据 schema 和主题安全参数，持久化失败时回滚原状态。
- FR-049：月度剩余额度小于 0 时页面显示“本月超支”与绝对值；其他情况显示“本月可用”。
- FR-050：预算周期起始日只能为 1–28；领域层必须派生当前周期起止日期和含今天剩余天数。
- FR-051：预算公式只聚合当前预算周期真实收支；自然月归档、月/年回看和账单导入结构保持兼容。
- FR-052：直接填写模式不得展示或保存明细；明细合计模式最多保存 12 条明细，总额必须等于有效明细合计；明细不生成流水。
- FR-053：页面不展示或编辑分类预算；保存预算时将兼容字段写为空数组。
- FR-054：根状态保存最多 8 个合法常用模板；模板通过独立 Promise 服务增删列出，页面不得直接访问缓存。
- FR-055：模板一键记账必须复用 `addTransaction({ action: 'create' })` 和既有幂等、防重复、失败状态。
- FR-056：周总结使用周一至今日与上周同期口径，只统计真实支出，并提供无基数的中性状态。
- FR-057：schema 1/2/3/4 无损迁移到 schema 5；旧预算默认为自然月周期，旧状态模板和两类明细为空。
- FR-058：首页原生导航栏标题留空，由安全区下方的页面标题展示产品名，避免 Android/Huawei 系统字体度量裁切和重复标题。
- FR-059：固定支出计算方式保存为 `manual | items`；旧数据缺少该字段时安全回退为 `manual`，跨月沿用和完整备份恢复不得丢失。
- FR-060：每日建议额度为 `max(固定收入 + 周期内额外收入 - 固定支出 - 储蓄目标, 0) ÷ 当前预算周期总天数` 向下取整到分；历史消费只影响今日剩余和周期省下，不改变该日均建议值。
- FR-061：周期省下金额为 `固定收入 + 周期内额外收入 - 固定支出 - 储蓄目标 - 周期内全部消费`；首页必须注明“已扣除储蓄目标”。
- FR-062：语音记账使用微信官方识别插件，点击开始/停止，并把最终识别文字送入既有快速记账解析与确认流程；不得直接保存识别结果。
- FR-063：语音插件缺失、麦克风拒绝、空识别或运行错误时必须提供可理解反馈，手动文字输入不得被禁用。
- FR-064：快速记账解析必须支持常见中文数字与多笔语句拆分；规则无法确定的内容不得自动保存。
- FR-065：多笔确认层允许逐笔选择和修改用途、金额、分类与时间，确认后仍通过既有 `addTransaction({ action: 'create' })` 逐笔写入。
- FR-066：外币解析生成人民币可编辑草稿，必须显示原币金额和参考汇率，不得声称实时。
- FR-067：照片入口使用 `wx.chooseMedia` 选择相机或相册图片；未配置安全服务端 OCR 时仅提供本地预览与手动核对，图片路径不持久化。
- FR-068：月度分析的日历金额、日均、最高日、最高分类和每日曲线必须只基于真实本地支出流水；收入和启用前汇总不得伪造成某日金额。
- FR-069：首次设置必须提供“先看看”；用户点击后将收入 800000 分、固定支出 80000 分、储蓄目标 200000 分作为可修改的本机预算写入，不添加消费或收入流水。
- FR-070：月度分析必须将真实当前日期与所选自然月分离；历史月份按完整月统计且不高亮伪造的“今天”，当前月仍按真实已过天数计算日均。
- FR-071：月历有效日期必须提供至少 88rpx 的可访问点击区域；未来日期禁用，所选日期有非颜色独占的明确选中态，月份切换时清除旧日期明细。
