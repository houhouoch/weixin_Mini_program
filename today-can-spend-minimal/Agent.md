# 今天还能花 · 简约版 Agent 规范

## 1. 产品边界

- 本目录是可单独导入微信开发者工具的独立小程序，不覆盖上层完整版。
- 产品核心问题仍是“今天还能安全花多少钱”，保持原生单页、本地存储、无登录、无云开发、无 tabBar。
- 现有预算、收支记录、历史纠错、日/月/年/自定义统计、微信/支付宝账单导入、Excel 导出、备份恢复、分享、主题、常用模板、固定支出明细和周总结能力必须保留。
- 不增加支付、广告、会员、AI 理财建议、个人钱包直连、银行直连或服务端。
- 账单与备份文件只在本机处理；不得保存平台交易单号原文、OPENID、头像、昵称或身份字段。

## 2. 体验目标

- 用户打开后 3 秒内看懂今日可用金额、今日已花和本周期余额。
- 高频“记一笔”默认展开；默认保留上次分类，模板仍可一键记录，减少一次展开操作。
- 回看与账本使用渐进披露；高级文件工具放在账本内，不与首页核心金额竞争。
- 同一层级只出现一个主操作；错误就近说明，异步操作必须有保存中/失败/成功反馈。
- 页面文案直接、短句、非羞辱性；不使用“稳稳生活”等装饰性口号替代真实数据。

## 3. 视觉规范

- 采用接近 Apple 系统应用的分组式简约界面：中性灰背景、白色内容面、系统字体、大数字、清晰分隔和充足留白。
- 默认色：背景 `#F5F5F7`、表面 `#FFFFFF`、正文 `#1D1D1F`、次级文字 `#6E6E73`、分隔 `#D2D2D7`、强调色 `#0066CC`。
- 一屏只使用一个可定制强调色；警示色和超支色由系统锁定，不能被主题覆盖。
- 不使用渐变、厚重阴影、彩色大面积模块、装饰性插画、虚线票据、连续高饱和卡片或 emoji 图标。
- 圆角仅用于分组容器和输入控件；边框 1px 等效，阴影只允许抽屉使用轻量层级。
- 主要触控区至少 `88rpx × 88rpx`，相邻触控区至少 `16rpx`；动画 150–240ms，并支持减少动态效果。
- 适配安全区、375px 窄屏、横屏、超长金额和大字号；不得横向滚动或让固定元素遮挡内容。

## 4. 技术约束

- 仅原生 JavaScript/WXML/WXSS/JSON；不引入第三方 UI 或运行时依赖。
- 金额统一用整数分；页面不得直接访问微信缓存或文件系统管理器。
- 交易服务仍只公开返回 Promise 的 `addTransaction()` 与 `listTransactions()`。
- 业务领域层和服务层从完整版复制后保持接口兼容；简约版使用独立存储 key，避免同一 AppID 下污染完整版数据。
- `trackEvent()` 不记录逐笔金额、预算金额、用途、平台订单号或身份信息。
- 分享 path 只允许 `pages/index/index?from=share`。

## 5. 状态与风险

- 必须覆盖读取中、首次空、读取失败、保存中、保存失败、保存成功、无记录、防重复、禁用、超支、额度将尽和导入/恢复失败。
- 余额风险不能只靠颜色表达；标题、金额文案、说明和状态标记必须同步变化。
- 交易是事实记录，即使导致超支也允许保存；预算设置仍执行收入、固定支出、储蓄目标和已记录交易的关联校验。
- 固定支出“直接填写”不展示明细；“明细合计”才显示明细并实时累计。

## 6. 完成定义

1. 新目录可以独立导入、编译和预览；
2. 原有 Node 测试全部通过，新增简约结构检查通过；
3. Automator 覆盖启动、核心金额、快速记账、折叠区、设置和 Console；
4. 生成开发者工具预览并区分模拟器、Console、预览包与真实手机结果；
5. 更新本目录 PRD、SDD、README、任务和验收矩阵；
6. 只提交本目录和本任务文件，保留上层项目的本地配置改动。
