# SDD 001：独立简约版重建

## 用户故事

### US1 首屏理解（P0）

- Given 已有有效预算，When 打开首页，Then 首屏显示今日额度、状态、今日已花和本周期可用/超支。
- Given 处于额度将尽、今日超额或周期超支，Then 标题、金额文案、说明和状态标记共同变化，不能只换颜色。
- Given 无有效数据或读取失败，Then 不展示伪造金额，并分别显示首次设置或可重试错误状态。

### US2 少操作记账（P0）

- 快速记账默认展开，不需要先点“展开”。
- 默认支出并保留最近分类；输入金额后即可保存，用途可选。
- 收入模式明确提示固定收入无需重复记录。
- 常用模板直接出现在首页，点击后只新增一笔并防重复。

### US3 回看与账本（P0）

- 回看与账本默认收起，展开后保留完整版所有日/月/年/自定义、历史、纠错、导入、导出和备份能力。
- 折叠标题使用文字说明当前状态，触控区至少 88rpx。

### US4 设置与主题（P0）

- 设置抽屉保持预算周期、固定收支、储蓄目标和两种固定支出模式。
- 直接填写不显示明细；明细合计实时累计。
- 主题仍有六套预设和安全微调，但页面始终使用中性表面、单强调色和锁定语义色。

### US5 隐私与数据兼容（P0）

- 简约版使用独立本地存储，不读取或覆盖完整版工作数据。
- 完整 JSON 备份仍可用于数据迁移。
- 分享、埋点、账单导入、Excel 和备份遵守原有隐私边界。

## 功能需求

- FR-001：仅一个页面，无 tabBar、第三方 UI、服务端或登录。
- FR-002：业务模块保持 Promise 接口和整数分计算；页面不直接访问缓存或文件系统管理器。
- FR-003：交易模块只公开 `addTransaction()` 与 `listTransactions()`。
- FR-004：首页顺序为标题 → 今日额度 → 预算摘要 → 常驻快速记账 → 折叠回看 → 折叠账本 → 分享。
- FR-005：页面只使用一个主题强调色；警示和危险色不可被主题覆盖。
- FR-006：按钮、输入、分段控制和折叠标题触控高度至少 88rpx。
- FR-007：异步操作均提供 loading/disabled/error/success；重复提交由页面锁和命令幂等共同阻止。
- FR-008：375px、横屏、大字号和 Android 安全区下无横向滚动与遮挡。
- FR-009：保留原版预算、交易、回看、历史、账单、导出、备份、主题、分享和迁移验收。
- FR-010：简约版存储 key 与完整版不同；备份格式标识保持兼容。

## 约束

- 原生 JavaScript/WXML/WXSS/JSON；无运行时第三方依赖。
- 同一 AppID 用于本机验证，但若要并行发布为两个小程序，需要在微信公众平台另行申请 AppID。
- 真机扫码、系统文件菜单、分享面板和大字号结果必须与模拟器证据分开报告。
